# Англо-русский глоссарий ML System Design

[Главная](README.ru.md) · [Конспект](BookOutline.ru.md) · [Шаблон](templates/basic_ml_design_doc.ru.md)

Глоссарий добавлен для русской версии. Пояснения составлены редактором перевода; это не отдельная глава книги. При первом упоминании допустимо указывать оба варианта: «базовое решение (baseline)». Названия библиотек, API, команды и пути файлов не переводим.

## Задача и продукт

| English | Русский вариант | Короткое объяснение |
| --- | --- | --- |
| ML System Design | Проектирование ML-систем | Проектирование данных, моделей, сервисов, проверок и эксплуатации как одной системы. |
| Problem statement | Постановка задачи | Какую проблему, для кого и с каким ожидаемым результатом решаем. |
| Problem space | Пространство проблемы | Потребности, контекст, цели и ограничения до выбора реализации. |
| Solution space | Пространство решений | Возможные способы решить проблему. |
| Stakeholder | Заинтересованная сторона | Пользователь, команда или организация, на которую влияет проект. |
| Scope | Границы проекта; объём работ | Что включено в текущую итерацию. |
| Antigoals / non-goals | Антицели; что не входит в проект | Явно исключённые задачи. |
| Functional requirements | Функциональные требования | Что система должна делать. |
| Non-functional requirements | Нефункциональные требования | Как она должна работать: задержка, доступность, безопасность и т. п. |
| MVP | Минимально жизнеспособный продукт | Минимальная версия, позволяющая проверить ценность решения. |
| Build or buy | Разрабатывать или покупать | Выбор собственной реализации или готового решения. |
| Trade-off | Компромисс | Улучшение одного свойства за счёт другого. |
| Technical debt | Технический долг | Отложенная работа, усложняющая дальнейшее развитие и сопровождение. |
| Failure mode | Сценарий отказа | Определённый способ, которым система может перестать выполнять задачу. |

## Данные и валидация

| English | Русский вариант | Короткое объяснение |
| --- | --- | --- |
| Dataset | Датасет; набор данных | Организованные данные для обучения или оценки. |
| Target | Целевая переменная; таргет | Величина, которую предсказывает модель. |
| Label | Метка | Значение класса или другого целевого результата у примера. |
| Labeling | Разметка | Получение меток для примеров. |
| Ground truth | Эталонные значения; истинные метки | Принятый эталон для проверки; он сам тоже может содержать ошибки. |
| Metadata | Метаданные | Сведения о происхождении, схеме, времени и других свойствах данных. |
| ETL | Извлечение, преобразование и загрузка | Последовательность подготовки и переноса данных. |
| Pipeline | Пайплайн; последовательность обработки | Связанные шаги обработки, обучения или применения модели. |
| Data freshness | Свежесть данных | Насколько текущие данные отстают от событий в источнике. |
| Data retention | Сроки и правила хранения | Как долго и на каких условиях сохраняют данные. |
| Data leakage | Утечка данных | Использование информации, недоступной в реальном сценарии предсказания или нарушающей независимость оценки. Не путать с раскрытием конфиденциальных данных. |
| Holdout | Отложенная выборка | Часть данных, не используемая для соответствующего этапа обучения. |
| Cross-validation | Кросс-валидация | Повторная оценка на нескольких разбиениях. |
| Nested validation | Вложенная валидация | Внутренний цикл выбирает настройки, внешний оценивает процедуру. |
| Adversarial validation | Проверка различий выборок классификатором | Обучаем модель отличать выборки и анализируем найденные различия. |
| Prediction horizon | Горизонт прогноза | На какой будущий период делается предсказание. |
| Temporal gap | Временной зазор | Промежуток между обучающими и проверочными данными. |
| Cold start | Холодный старт | Мало истории для новой системы, пользователя или объекта. |
| Representativeness | Репрезентативность | Насколько выборка отражает условия, для которых предназначена система. |

## Модели и оценка

| English | Русский вариант | Короткое объяснение |
| --- | --- | --- |
| Baseline | Базовое решение | Простой или текущий вариант, с которым сравнивают улучшения. |
| Constant baseline | Константное базовое решение | Ответ не зависит от входных признаков, например всегда медиана. |
| Feature | Признак | Входная характеристика для модели. |
| Feature engineering | Конструирование признаков | Создание и преобразование признаков. |
| Feature selection | Отбор признаков | Выбор полезного подмножества признаков. |
| Feature importance | Важность признаков | Оценка вклада признака; её смысл зависит от метода. |
| Feature store | Хранилище признаков | Инфраструктура управления и выдачи признаков. |
| Loss function | Функция потерь | Критерий, который оптимизируют при обучении. |
| Metric | Метрика | Числовой показатель качества модели, системы или продукта. |
| Proxy metric | Proxy-метрика; косвенный показатель | Доступное приближение к интересующему результату. |
| Offline evaluation | Offline-оценка | Проверка на подготовленных данных до взаимодействия с реальным трафиком. |
| Online evaluation | Online-оценка | Проверка работающей системы на реальных взаимодействиях. |
| Guardrail metric | Метрика-ограничение | Показатель, который защищает от нежелательных последствий изменений. |
| Residual | Остаток | Разница между наблюдением и предсказанием; знак нужно определить явно. |
| Outlier | Выброс | Наблюдение, сильно отличающееся от основной массы. |
| Overfitting | Переобучение | Подгонка под обучение, не дающая соответствующего качества на новых данных. |
| Underfitting | Недообучение | Модель недостаточно хорошо описывает даже доступные закономерности. |
| Bias–variance trade-off | Компромисс смещения и разброса | Баланс систематической ошибки и чувствительности результата к обучающей выборке. |
| Learning curve | Кривая обучения | Зависимость качества от итераций, размера данных или другого параметра процесса. |
| Transfer learning | Перенос обучения | Использование знаний модели, полученных на другой задаче или данных. |
| Fine-tuning | Дообучение | Адаптация уже обученной модели. |
| Zero-shot / few-shot | Без примеров / с малым числом примеров | Режимы решения задачи без целевых примеров или с небольшим их числом; детали зависят от метода. |
| Hyperparameter | Гиперпараметр | Настройка алгоритма обучения, обычно выбираемая вне оптимизации весов. |
| Experiment tracking | Учёт экспериментов | Хранение параметров, версий, метрик и артефактов запусков. |
| Uplift | Прирост; дополнительный эффект | В отчёте может означать разницу метрик, а в причинном моделировании — эффект воздействия. Уточняйте контекст. |
| Consistency metric | Метрика согласованности | Проверка стабильности поведения при изменениях входа или повторном обучении. |

## Эксплуатация

| English | Русский вариант | Короткое объяснение |
| --- | --- | --- |
| Inference | Инференс; получение предсказаний | Применение обученной модели к входным данным. |
| Serving | Обслуживание запросов к модели | Работа сервиса, который принимает входы и выдаёт предсказания. |
| Deployment | Развёртывание | Подготовка и запуск версии системы в целевой среде. |
| Latency | Задержка | Время от запроса до результата; границы измерения указывают явно. |
| Throughput | Пропускная способность | Число обработанных запросов или событий за единицу времени. |
| Scalability | Масштабируемость | Возможность справляться с ростом нагрузки и данных. |
| Batch processing | Пакетная обработка | Обработка накопленной группы данных. |
| Streaming | Потоковая обработка | Обработка поступающих событий по мере их получения или небольшими окнами. |
| Batching | Объединение в батчи | Совместная обработка нескольких запросов или примеров. |
| Caching | Кеширование | Сохранение результатов для повторного использования. |
| Model routing | Маршрутизация между моделями | Выбор модели для конкретного запроса. |
| Quantization | Квантование | Представление чисел с меньшей точностью для снижения вычислительных расходов. |
| Fallback | Резервный сценарий | Запасной режим работы при отказе или неподходящих условиях. |
| Override | Принудительная корректировка | Замена или изменение решения модели по внешнему правилу или вручную. |
| Rollback | Откат | Возврат к предыдущей рабочей версии. |
| Canary deployment | Постепенный выпуск на малую долю трафика | Проверка версии на ограниченном объёме реальных запросов. |
| Blue-green deployment | Развёртывание в двух средах | Переключение между старой и новой подготовленной средой. |
| SLA | Соглашение об уровне обслуживания | Согласованные обязательства по качеству сервиса. |
| Data drift | Дрейф данных | Изменение распределения входных данных. |
| Concept drift | Дрейф концепции | Изменение связи между входными данными и целевым результатом. |
| Model decay | Ухудшение качества модели со временем | Наблюдаемое снижение качества; причину нужно исследовать. |
| Training-serving skew | Расхождение признаков при обучении и применении | Различия в расчёте, доступности или значениях признаков между двумя режимами. |
| Smoke test | Проверка основной работоспособности | Быстрая проверка, что ключевой путь выполняется. |
| Property-based testing | Тестирование свойств | Проверка общих свойств на множестве генерируемых входов. |
| Human-in-the-loop | Участие человека в процессе | Человек проверяет, корректирует или принимает часть решений. |
| Ownership | Ответственность за систему | Явное назначение владельцев и обязанностей по развитию и эксплуатации. |
| RACI | Матрица распределения ответственности | Кто выполняет работу, отвечает за результат, консультирует и получает информацию. |
| Bus factor | Фактор зависимости от ключевых людей | Сколько людей может выбыть, прежде чем проект остановится из-за потери знаний; низкое значение опаснее. |
